-## Warmup Wave (F13-F22): gem5-style `--vsim-warmup-icount`
-
-Motivation: today vsim's reported cycle figure (`mcycle` delta across the ROI)
-includes the cold-cache/cold-BPU/cold-TLB prefix at vsim entry. `docs/USER_GUIDE.md`
-and `docs/switching_modes_tutorial.md` document this as an accepted limitation.
-gem5's equivalent is `--warmup-insts N`: run N functional insns on the
-fast-forward CPU, then `m5.stats.reset()` at the switch boundary. Hybrid_sim's
-constraint differs: QEMU has no cache model, so warmup MUST happen inside vsim.
-The solution is a measurement-start snapshot of `mcycle/minstret` K insns after
-vsim entry; cache stays warm because vsim is one process, only the stats
-window moves. Wire format size is preserved (uses bytes from `reserved[232]`).
