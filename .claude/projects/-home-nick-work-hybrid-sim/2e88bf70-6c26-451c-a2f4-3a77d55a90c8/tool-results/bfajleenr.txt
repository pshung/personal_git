### L14. The SimPoint cycle estimate is an approximation, not a measurement

- Where: `hsim.py:1126-1225` (`_run_simpoint_pipeline`). Note: SimPoint

### L26. [RESOLVED 2026-06-16] V transport scratch moved above the program's RAM  (new 2026-06-15)

- **Was**: the V-register transport staged 32 vector registers through a fixed
  guest address `kVScratchGpa = 0x00FF0000` (15 MiB), INSIDE the program's RAM.
  On every resume on a V-capable core -- the V flag is set from register
  ADVERTISEMENT, not use, so even a program that issues no V instruction
  triggers it -- `ResumeDriver` wrote the drained V bytes there, silently
  clobbering any program data at that address. Repro: `break_vscratch.S`.
- **Why a scratch page is needed at all**: the RISC-V Debug Module has no
  abstract command for `v0..v31`, so vsim moves them by executing `vle8.v` /
  `vse8.v` in the Program Buffer against a known guest-RAM staging page
  (`v_regfile_xfer.hpp`, `program_buffer.hpp`).
- **Fix (scheme D; F1+F2+F3, see `docs/archive/vscratch_reservation.md`)**:
  1. The scratch is no longer a constant -- it is the TOP page of the mapped
     RAM span, `v_scratch_gpa(ram_base, ram_size) = ram_base + ram_size -
     HYBRID_V_SCRATCH_BYTES`. ResumeDriver/StateDrain take it as a required-
     when-V argument; a V handoff with it unset throws (no silent transport
     through a bogus address).
  2. The driver maps ONE PAGE MORE than `--mem-size` (`shm.cpp`
     `physical_mmap_bytes`), so the scratch sits at `ram_base + --mem-size` --
     just ABOVE the program's declared RAM. No program layout (low stack,
     top-of-RAM stack, or a heap grown to the ceiling) can reach a page past its
     own RAM, so the scratch can never be clobbered. `--mem-size` is capped at
     2 GiB minus the page.
  3. A load-time guard (`elf_load_top` + `cmd_run.cpp`) rejects an ELF whose
     static image extends into the reserved page (linked for more RAM than
     `--mem-size` grants) with a clear "raise --mem-size" message, instead of
     silent corruption.
- **Effect on users**: none visible -- you get your full `--mem-size`; the
  reservation is one hidden page the simulator adds on top, and no address
  within your declared RAM is off-limits.
- **Tests**: `v_regfile_xfer` / `resume_driver` / `state_drain` unit suites
  (top-page GPA + unset guard); `infra-test` (physical size + cap); `elf-syms`
  (load-top + reject). `break_vscratch.S` now PASSES (0x00FF0000 is no longer
  used); new `break_vscratch_top.S` PASSES (a sentinel at the program's LAST
  page survives the transport, proving the scratch sits above program RAM);
  full marker e2e 22/22 + V e2e 4/4.
- **Status**: RESOLVED (2026-06-16).

### L25. ROI code that reads or writes time-variant CSRs produces engine-dependent results  (new 2026-06-15)

- **The rule**: code inside the ROI must treat `mcycle` (0xB00), `minstret`
  (0xB02), `mip` (0x344), and `time` (0xC01) as opaque.  No branches,
  arithmetic, or writes on these CSRs inside the ROI.
- **Why**: QEMU approximates both cycle and instruction counts with a CPI≈1
  model; vsim counts actual RTL pipeline cycles and retires.  `mip` pending
  bits (MTIP, MEIP, MSIP) reflect live timer/platform state that differs
  between QEMU's functional clock and vsim's cycle clock.  These values
  diverge at every architectural moment inside the ROI -- by construction,
  not by bug.
- **What happens if the rule is broken**:
  - *Branch on `mcycle`/`minstret`*: the `--verify` oracle (pure QEMU)
    takes a different branch than the hybrid run (vsim); the diff reports a
    GPR or PC mismatch.  The plain run passes; only `--verify` exposes it.
  - *Write `mcycle`* (e.g. `csrw mcycle, zero` to reset a performance
    counter): `StateDrain` re-reads the reset value at the exit marker; the
    reported cycle delta is near-zero or underflows -- silently wrong.
- **Where**: any `csrr`/`csrw` on `mcycle`, `minstret`, `mip`, or `time`
  between the entry and exit markers.
- **Demonstrated by**: `tests/fixtures/break_mcycle_write.S` (write corrupts
  delta), `tests/fixtures/break_verify_diverge.S` (branch diverges under
  `--verify`).
- **Distinction from L22**: L22 is about async interrupts in the lock-step
  DV path; L25 is about the hybrid measurement path and any code that reads
  or modifies time-variant state inside the ROI.
- **Status**: by design.  A static linter on the ELF could warn on in-ROI
  reads/writes of these CSRs (not built).

### What blocks commercial shipping

1. **Silent correctness gaps.** ~~`fcsr/frm/fflags` never round-trip
   (L20)~~ - resolved 2026-06-12; `fcsr` now transports and `--verify`
   compares it. Still standing: `cmderr` is W1C-cleared so a partial CSR
   restore is observable only through a private counter
   (`resume_driver.hpp:196-205`).
2. **ROI envelope is too narrow.** ~~M-mode only~~ (S/U privilege
   transports since L6, 2026-06-13, on an S/U-capable engine), but "no
   traps, no paging, no semihosting inside the window" (L1-L5) still
   rules out every real OS-bearing benchmark - SPEC under Linux, any
   driver code, anything with page faults. The vplat runtime covers
   bare-metal I/O only.
3. **No Andes vendor CSRs.** For an Andes product, shipping zero
   `mmsc_cfg / mcache_ctl / mmisc_ctl` transport (L21) is a
   credibility hit and an accuracy hazard - cache and prefetcher
   controls shape the cycle count.
4. **Only 11 CSRs restored into vsim** (mstatus, mtvec, mscratch, mepc,
   mcause, mtval, mie, mip, mcycle, minstret, fcsr), plus `dcsr.prv` and
   - for S/U handoffs - the PMP block (L6, 2026-06-13). `satp` and
   `medeleg/mideleg` (S-mode CSRs the M-only default engine lacks; and
   PMP on M-mode handoffs) are drained but never written back into vsim
   (`resume_driver.hpp`). They exist in the wire format but not in the
   simulator. Any future need for paging or S-mode delegation inside
   the ROI needs `resume_driver` extended.
5. **Wire format is v1-locked with ad-hoc growth.** Each new field
   steals from `reserved[]` (warmup metadata ate 16 bytes, fcsr another
   8; `state_abi.h`). No deprecation path, no feature bits beyond
   the three `HYBRID_FLAG_*` bits.
6. **Build/test infrastructure is single-host.** Podman-required vsim
   build, hardcoded `JOBS=8` ceiling on 128-core hosts,
   `/dev/shm`-backed fixtures - all fine for a lab, painful for a
   commercial CI matrix.

### What it does well (the 7/10 internal-tool score)

- Two-phase handoff is a clear, documented contract.
- `state_abi.h` plus `static_assert`s pin layout - good ABI hygiene.
- The team writes down what does NOT work (this notebook, 22 entries plus
  the state-coverage section) instead of hiding it. Commercially that
  is the release-blocker checklist; internally it is exemplary.
- SimPoint integration for whole-program cycle estimation (L14) is a
  real differentiator over a pure functional sim.

### Bottom line

Ship-grade architecture, research-grade coverage. For commercial
release you need:

- v2 wire format with feature bits and a deprecation path
- traps + paging supported inside ROI (close L3, L4);
  ~~privilege transport (L6)~~ done 2026-06-13
- Andes vendor CSR transport (close L21)
- ~~`fcsr` fix (close L20)~~ done 2026-06-12
- A proper error policy instead of `cmderr` swallowing
- The existing `--verify`/`--cosim` oracle (L15) extended to
  icount/simpoint and wired into CI

Rough effort: 6-9 months of focused hardening, not weeks.
